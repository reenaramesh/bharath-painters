What changed and why

1. Section tiles (3×3 grid, 9 items, ~590px before any work) became a sticky rail with live counts — every section and its size visible at once. 2. The add form was permanently expanded above the list; it is now behind Add entry. 3. The upload card always occupied a full panel; it is now behind Import CSV. 4. Product Types and Work Descriptions drilled Section → category card → modal → card. They now use the same flat list as every other section, with service type as a chip filter. 5. The repeated violet “Your entry / Shared master” line on every row became a small coloured dot. 6. Terms and Conditions left the section list — it is not a list of entries. 7. Added Active / Inactive per row, with All / Active / Inactive chips so switched-off entries stay findable.

Backend note — the toggle itself already works, but listing inactive rows does not

is_active already exists on all eight models (MasterDataBase) and is writable through the current PATCH, so no migration is needed. Two gaps block this UI: the list endpoints filter is_active=True, so a deactivated entry disappears and can never be switched back on — that needs an ?include_inactive=1 (or ?status=) filter on visible_master_data(). And the apartments endpoint has no serializer; its PATCH only whitelists name, pincode, locality and zone, so is_active must be added there. Apartments are admin-only, hence the disabled control and padlock.
